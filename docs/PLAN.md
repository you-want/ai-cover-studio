# 声替 CoverMe（AI 翻唱工坊） · 项目规划与实施方案

> 一句话定位：克隆你自己的声音，翻唱你喜欢的歌 —— 全程本地处理，不上传云端。

## 1. 背景与目标

**用户故事**：我录一段 10~30 秒的自己的人声 → 选一首喜欢的歌 → 软件把歌里的原唱人声换成"我的音色唱出来的效果" → 试听、分轨对比、下载成品。

**核心目标**

| # | 目标 | 验收标准 |
|---|------|----------|
| G1 | 歌曲内人声/伴奏分离 | 得到干净的人声轨与伴奏轨（自动回退保证总能出结果） |
| G2 | 声音克隆（零样本） | 录音即可克隆，无需训练；保留旋律与节奏，替换音色 |
| G3 | 自动混音成曲 | 人声轨转换后与伴奏对齐混音、响度归一、导出 wav/mp3 |
| G4 | 开箱即用的产品形态 | Web UI（录音→选歌→生成→试听/下载）+ CLI，双入口 |
| G5 | 弱环境可用 | 无 GPU、无外网、无高质量模型时也能跑通全流程（演示级效果） |

**非目标（v1 不做）**：歌词对齐/逐字合成、移动端 App、云端多用户、训练自定义声学模型（列入路线图）。

## 2. 技术选型与决策

### 2.1 翻唱流水线（业界通行架构）

```
原歌曲 ──► ① 人声/伴奏分离 ──► ② 声音转换(SVC/音色迁移) ──► ③ 混音/母带 ──► 翻唱成品
                (Demucs)          (克隆你的音色)              (对齐/响度/导出)
```

### 2.2 声音克隆方案对比（2026 主流开源方案）

| 方案 | 需要训练 | 歌唱效果 | 依赖重量 | 决策 |
|------|:---:|:---:|:---:|------|
| **RVC / so-vits-svc** | 需要（每人 10~30 分钟训练） | ★★★★★ | 中（fairseq 较难装） | 路线图：作为"训练模式"接入 |
| **Seed-VC** | 否（零样本） | ★★★★★（SVC 模式保唱腔） | 大（torch + 模型 2GB） | ✅ 接入为最优引擎（实验性） |
| **OpenVoice v2** | 否（零样本） | ★★★★（音色迁移保旋律） | 中（torch + 500MB） | ✅ 接入为默认高质量引擎 |
| **DSP 音域适配** | 否 | ★★（演示级） | 零（纯 numpy/scipy） | ✅ 永远可用的兜底引擎 |

**决策理由**：
1. 用户录一段就能用 → 必须零样本，RVC 类训练方案放路线图；
2. 引擎做成**插件架构**（统一 `BaseVoiceEngine` 接口），按质量优先级自动选择，任何引擎安装失败都优雅降级到下一个，**绝不阻塞产品可用性**；
3. 目标机器为 Intel Mac（无 CUDA/MPS），纯 CPU 推理，OpenVoice 单曲几十秒可接受。

### 2.3 人声分离方案

| 方案 | 质量 | 成本 | 决策 |
|------|:---:|------|------|
| **Demucs v4 (htdemucs)** | 高 | torch ~2GB + 模型 80MB，CPU 每分钟歌约 1~3 分钟 | ✅ 默认 |
| 中心声道提取（卡拉OK式） | 演示级 | 纯 DSP，秒级 | ✅ 兜底（分离失败自动回退） |

### 2.4 工程栈

- **后端**：Python 3.12 + FastAPI + SQLite（任务持久化）+ 线程池任务队列
- **音频核心**：numpy/scipy 自研 DSP（WSOLA 变速变调、FFT 自相关基频检测、RBJ 均衡、BS.1770 LUFS 响度、前瞻软限幅）—— 不依赖 librosa/numba，核心链路零重依赖
- **格式**：soundfile 为主，ffmpeg 兜底（系统无 ffmpeg 时自动用 imageio-ffmpeg 内置二进制）
- **前端**：原生 HTML/CSS/JS 单页应用（零构建链），MediaRecorder 浏览器录音
- **测试**：pytest（24 例，含走 HTTP 全链路的端到端测试）

## 3. 系统架构

```
┌────────────────────────── 浏览器 (app/web) ──────────────────────────┐
│  ① 录音(MediaRecorder)/上传声音样本  ② 拖拽选歌  ③ 引擎/参数设置    │
│  ④ 任务进度轮询  ⑤ 成品播放/下载/分轨对比                            │
└──────────────────────────────┬───────────────────────────────────────┘
                               │ REST (JSON + multipart)
┌──────────────────────────────▼──────────── app/main.py (FastAPI) ────┐
│  /api/engines  /api/voice-samples  /api/covers(/result,/stems)       │
│  任务队列 Pipeline(SQLite 状态机, 线程池)                            │
└──────────────┬───────────────────────────────┬───────────────────────┘
               │                               │
   ┌───────────▼──────────┐        ┌───────────▼────────────────────┐
   │ separation/ 分离器    │        │ voice/ 声音引擎（插件化）       │
   │  DemucsSeparator     │        │  SeedVCEngine (实验, 最优)      │
   │  CenterExtract(兜底) │        │  OpenVoiceEngine (零样本克隆)   │
   └──────────────────────┘        │  PitchFitVoiceEngine (永远可用) │
                                    └────────────────────────────────┘
   audio/ 基础层: io(解码/导出) · dsp(WSOLA/基频/滤波/响度) · mix(混音/母带)
```

**流水线六阶段**（UI 实时显示进度）：预处理 → 声音分析 → 轨道分离 → 声音转换 → 混音 → 导出。
每阶段失败都有回退策略并写入任务日志（notes）向用户透明展示。

## 5. 风险与对策

| 风险 | 对策 |
|------|------|
| HuggingFace/GitHub 在国内不可达 | 模型下载走 hf-mirror.com 镜像（默认）；可选组件安装失败不阻塞核心功能 |
| 无 GPU、CPU 推理慢 | 并发=1 的任务队列；进度实时反馈；分离器可切换快速兜底模式 |
| 高质量组件依赖冲突（gradio/fairseq） | openvoice 用 `--no-deps` 精准安装依赖；引擎懒加载，不装也不影响其他功能 |
| 音色克隆被滥用（克隆他人声音） | 界面明示仅限本人声音样本；成品仅限个人学习娱乐；不提供任何云端传播能力 |
| 上传超大文件 | 流式写入 + 150MB 大小上限 + 12 分钟时长上限 |

## 6. 路线图（v1.x）

1. **RVC 训练模式**：录音 ≥10 分钟 → 本地训练个人声学模型 → 挂载为新引擎（`BaseVoiceEngine` 接口已预留）
2. **Seed-VC SVC 模式**：当前以 VC 模式调用（仓库版本无 `--inference-mode svc`）；换用完整版仓库并开启 F0 条件（`--f0-condition --auto-f0-adjust`）可获得唱腔级迁移
3. **歌词逐字对齐**：接入 whisper 时间戳，实现"逐字音高修正"
4. **转换后人声超分**：接入 resemble-enhance 等做音质增强（LUFS 母带与噪声门已就位，可作为增强前置）
5. **A/B 对比播放器**、**作品导出分享卡片**、**同一任务参数微调重跑**（复用分离缓存秒级出片）
